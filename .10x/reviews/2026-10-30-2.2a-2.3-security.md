# Security review: tasks 2.2a and 2.3

- **Date:** 2026-10-30.
- **Scope:** `main` at `9f210b0` against `48a72ab`. That covers task 2.3 (`48c00e0`), task 2.2a (`70fb5bf`), the QA fixes (`049c165`) and the deploy change (`b2e3e19`).
- **Reviewer:** the lead session, as the security engineer, after the QA gate. The QA reports already checked the network, the user's audio and the font licenses. This review adds the threat model and a check of what the public site holds.
- **Verdict: pass.** Nothing blocks. One Low and one Info item.

## Threat model
The app has no accounts, no server and no telemetry. What these two tasks could break:

| Asset | Threat | Where it stands |
| --- | --- | --- |
| The private source code | It leaks through the public site repo | The site repo holds 77 files at "Publish web build 9f210b0", checked by its file list on 2026-10-30: no `.dart` file, no source map, no `lib/`, `.10x/` or docs. `flutter build web --release` writes no source maps, and the deploy job publishes only `build/web` |
| The user's songs and voice messages | The library sync saves over them or deletes them | `planLibrarySync` skips a clip when a song or voice message has its id (a clash). Three tests cover it |
| The user's privacy on the web | The page tells a third party that someone opened it | At start the site asks only its own host. CanvasKit, the fonts and the clips come from `aseke-quick.github.io`: the live `flutter_bootstrap.js` has `"useLocalCanvasKit":true` (2026-10-30), and the merge session's check counted 18 requests, all to that host. Low 1 is the one exception |
| The supply chain | A new package or a downloaded file brings code or content nobody checked | `pubspec.lock` did not change. The fonts are pinned files from `google/fonts`, with their SHA-256 in docs/DECISIONS.md 2.2a. Our own tool makes the clips, and it downloads nothing |
| CI and its token | A workflow change widens what CI may do | The `ci.yml` changes are one more test file in the DST step, `--no-web-resources-cdn` and the README text. No new secret, permission or action |
| The logs | The browser console shows user data | The sync logs clip ids only, or the error when the database cannot open. Labels, songs and voice messages never go to the log |

## Findings
1. **Low: a glyph that no bundled font has makes the web engine download a Noto font from `fonts.gstatic.com`.** A label with an emoji or a non-Latin letter is enough. Google then learns the visitor's address and the script that was needed, but not the label. The native apps never download a font. docs/DECISIONS.md 2.2a records it. Fix it when it matters: bundle a Noto subset, or block the request with Info 2 and accept a box in place of the glyph.
2. **Info: the site has no Content-Security-Policy.** GitHub Pages cannot set headers, but a `<meta http-equiv="Content-Security-Policy">` in `web/index.html` can. It would let the page reach only its own host, so "no request to another host" becomes a rule the browser enforces instead of a measured fact. It needs a test with CanvasKit (`'wasm-unsafe-eval'`) and the drift worker first.
