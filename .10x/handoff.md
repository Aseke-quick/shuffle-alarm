- **How to check:** build as the deploy job does (`--no-web-resources-cdn`); headless Chrome with a fresh profile and `--autoplay-policy=user-gesture-required`, driven by `cdp.dart`. The runs of this task are in `task-2.5a-tools/` in the 2.2a session's notes folder, next to those of 2.5, each with what it checks at its top. New: `log.sh` also shows the plans; `plan_check.py <db>` compares a log with its plan; `shown_check.py <log> <db>` compares it with what the page showed; `run_upgrade.sh` opens a database of the live build with the new build; `run_live_before.sh` and `run_live_after.sh` do that on the real site around a deploy. **Start Chrome runs some seconds apart:** three at the same moment made one page fail to load `main.dart.js`. To test what a new visit reads from IndexedDB, use a new browser on the same profile: the shared worker keeps the database in memory (`run_corrupt.sh`).
- **Remaining risks:** Safari and Firefox are untested. Chrome plays sound after any earlier tap on the site, so the blocked path is tested by widget tests and a stubbed context only. A closed, discarded or frozen tab neither rings nor reminds. Two open tabs ring and log twice, and show a change of the mix only at their next read. A hidden tab can find a ring up to about a minute late, and it then skips the clips before that moment.
- **Release readiness:** the web test version rings by its plan; nothing open blocks it. Anyone with the link can use and copy the web version.
